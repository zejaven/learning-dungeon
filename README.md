# Java Interview Dungeon — interactive interview-prep learning engine

Turns Java interview questions into interactive, visual learning **topics**. Each
topic has an explanation, a runnable code editor, a sandboxed Java runner, and a
**visualization** that replays what the code did, step by step — plus missions and
an AI helper. New topics are generated by Claude Code from a single pasted question.

The architecture: a fixed **shell** + reusable **visual primitives** + controlled
**learning models** (instrumented wrappers) that emit **trace events**. Code never
drives the UI directly; it produces an event stream the UI plays back. See
[`IMPLEMENTATION-PLAN.md`](./IMPLEMENTATION-PLAN.md).

## Layout

```
backend/         Spring Boot API: /api/run, /api/topics, /api/topics/generate (SSE), /api/assistant/ask (SSE)
visual-runtime/  Dependency-free Java learning models (e.g. VisualHashMap) that emit @@TRACE@@ events
frontend/        React + TypeScript + Vite + Monaco shell and visual primitives
topics/<id>/     One folder per topic: topic.yaml, explanation.md, examples/, visualizer.tsx, trace-schema.json, quiz.yaml
prompts/         add-topic.md (strict Claude Code contract) + topic-contract.md (schema reference)
```

## Prerequisites

- JDK 21 (the backend uses the JDK compiler API and forks a child JVM to run code)
- Node 18+ / npm
- [Claude Code](https://claude.com/claude-code) CLI on PATH (for the "Add topic" and "Ask AI" features)

## Run (local)

```powershell
./dev.ps1
```

This builds the `visual-runtime` jar, starts the backend (`:8080`) and the frontend
(`:5173`). Then open **http://localhost:5173**.

Or manually, in two terminals:

```powershell
./gradlew :visual-runtime:jar
./gradlew :backend:bootRun
```
```powershell
cd frontend; npm install; npm run dev
```

## How it works

- **Run** compiles the editor's `Playground` class (JDK compiler API) and runs it in a
  separate JVM with a heap cap and timeout. The `visual-runtime` jar is on its classpath
  so user code can drive `VisualHashMap` etc., which print `@@TRACE@@{json}` events.
- The backend splits those events from normal output and returns them; the frontend
  replays them through the topic's `visualizer.tsx`, built from `ArrayGrid` / `LinkedNodes`
  / `EventLog` primitives.
- **Missions** complete when a run produces a matching trace event (e.g. `HASHMAP_COLLISION`).
- **Ask AI** streams an answer from Claude Code about the current topic.
- **Add topic** streams a Claude Code run that scaffolds `topics/<id>/` from a pasted
  question, following `prompts/add-topic.md`. Reload to load the new topic's visualizer.

## Adding a topic by hand

Run Claude Code at the repo root with the contract and your question:

```powershell
Get-Content prompts/add-topic.md | claude -p
```

Then paste the interview question when prompted, or append it to the prompt.

## Notes / not yet done (post-MVP)

- This is a **local personal tool**. The runner relies on a timeout + heap cap + child
  process, not full container isolation. Don't expose it publicly as-is.
- The add-topic flow runs Claude Code with `--permission-mode bypassPermissions`
  (configurable via `app.claude.generate-permission-mode`) so it can write files headlessly.
- Source transformation (`new HashMap<>()` → `VisualHashMap`), multi-file projects, and
  additional topic types/primitives are future work.

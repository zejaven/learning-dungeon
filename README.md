# Java Interview Dungeon — interactive interview-prep learning engine

Turns Java interview questions into self-contained, interactive learning
**topics**: theory, a sandboxed code runner, step-by-step **visualizations**, SQL
and coding exercises, a Duolingo-style **micro-actions lesson** mode, a global
review pool, and an AI helper. New topics — and the lessons inside them — are
generated by a coding-agent CLI from a single pasted question.

The core idea for runnable topics: a fixed **shell** + reusable **visual
primitives** + controlled **learning models** (instrumented wrappers) that emit
**trace events**. Code never drives the UI directly; it produces an event stream
the UI plays back. See [`IMPLEMENTATION-PLAN.md`](./IMPLEMENTATION-PLAN.md) and,
for the lesson mode, [`plans/learn-by-micro-actions.md`](./plans/learn-by-micro-actions.md).
Instructions for AI coding agents live in [`AGENTS.md`](./AGENTS.md).

## Layout

```
backend/         Spring Boot API (Java 21): runs snippets, analyzes structural
                 topics, runs SQL in disposable H2 DBs, tracks progress in
                 PostgreSQL, serves/generates lessons, and calls a coding-agent CLI
visual-runtime/  Dependency-free Java learning models (e.g. VisualHashMap) that emit @@TRACE@@ events
frontend/        React + TypeScript + Vite + Monaco + Mermaid shell, stores, and visual primitives
topics/<id>/     One folder per topic (163+ today): metadata, explanations, code,
                 missions, boss-fight questions, an optional learning-atoms.json lesson, visualizer
prompts/         Strict generation contracts (add-topic.md, topic-contract.md,
                 generate-learning-atoms.md, mermaid-guide.md)
launcher/        Packaged tray run: build-app.ps1, tray.ps1, update.ps1, install-shortcut.ps1
config/          secret.example.yml → copy to secret.yml for local DB credentials
```

## Topic modes

A topic declares a `mode` in its `topic.yaml`:

- **trace** (default): runnable `Playground` examples plus a trace visualizer that
  replays what the code did, step by step.
- **structural**: design-pattern / class-relationship practice; multi-file Java
  compiled and analyzed with JavaParser into a class graph.
- **theory**: explanation plus a Boss Fight (AI-graded questions) only.
- **sql**: a seeded query playground against a fresh in-memory H2 database.
- **challenge**: a coding kata — the learner's `Solution.java` is compiled against
  a hidden harness and graded case by case.

Any mode may also carry a `learning-atoms.json`, which switches the topic's
default view from the long-form explanation to a **micro-actions lesson**:
8–15 "knowledge atoms" rendered as a sequentially-unlocked circle track of
prediction-first exercises, ending in the topic's Boss Fight. Practice exercises
of fully completed lessons feed a global, cross-topic **review** pool (`#/review`)
with wrong-answer requeueing.

## Prerequisites

- **JDK 21** — the backend uses the JDK compiler API and forks a child JVM to run
  code, so a JRE is not enough.
- **Node 18+ / npm**.
- **PostgreSQL** (local) for progress persistence. Copy `config/secret.example.yml`
  to `config/secret.yml` and fill in your credentials; `launcher/create-db.ps1`
  can create the database.
- A **coding-agent CLI** on `PATH` for Add Topic, Ask AI, lesson/style generation,
  and the usage meter. Supported providers: [Claude Code](https://claude.com/claude-code)
  (`claude`), OpenAI Codex (`codex`), and Kimi (`kimi`); the app picks an available
  one and lets you switch in the header.

## Run (local dev)

```powershell
./dev.ps1
```

This builds the `visual-runtime` jar, then starts the backend (`:18080`) and the
Vite frontend (`:15173`) in their own windows, freeing those ports from a previous
run first. Open **http://localhost:15173**.

The ports are intentionally not the 8080/5173 defaults, so other local projects
can keep those.

Or manually, in two terminals:

```powershell
./gradlew :visual-runtime:jar
./gradlew :backend:bootRun
```
```powershell
cd frontend; npm install; npm run dev
```

## Run (packaged, single process)

For everyday use there is a windowless tray build: one JVM on `:18080` that serves
both the API and the built frontend (bundled into the jar), with no Vite.

```powershell
launcher\build-app.ps1            # build the jar + frontend bundle
launcher\install-shortcut.ps1     # once: create the desktop/tray icon
```

Then launch from the icon. The tray keeps the server alive and, via the in-app
**settings gear**, can rebuild and restart itself — or pull the latest commits
from GitHub first (see "Self-update" below).

### Access from other devices on the LAN

Both servers listen on all interfaces, so another device on the same Wi-Fi (a
laptop, phone, or VR-headset browser) can open the app by the host PC's IP:
`http://<pc-ip>:18080` for the packaged run, or `http://<pc-ip>:15173` for the dev
server. Allow the port through the firewall on the host.

## How it works

- **Run** compiles the editor's `Playground` class (JDK compiler API) and runs it
  in a separate JVM with a heap cap and timeout. The `visual-runtime` jar is on
  its classpath, so user code can drive `VisualHashMap` etc., which print
  `@@TRACE@@{json}` events.
- The backend splits those events from normal output and returns them; the
  frontend replays them through the topic's `visualizer.tsx`, built from
  `ArrayGrid` / `LinkedNodes` / `EventLog` primitives.
- **Missions** complete when a run produces a matching trace event (e.g.
  `HASHMAP_COLLISION`). Lesson discovery/practice exercises are graded
  deterministically on the frontend; **Boss Fight** answers are graded by the AI.
- **Ask AI** streams an answer about the current topic (optionally scoped to
  selected text). **Add topic** and **✨ Generate lesson** stream a coding-agent
  run that writes `topics/<id>/` files following the `prompts/` contracts; the
  backend rereads `topics/` per request, so new content appears without a restart.
- Progress (missions, lesson/unit completion, Boss Fight, review pool) persists in
  PostgreSQL. User-facing content is bilingual (English / Russian).

## Self-update (settings gear)

The packaged run can update itself from the header ⚙️:

- **Update** — pull the latest commits from GitHub, rebuild, and restart.
- **Restart** — rebuild from the current local files and restart.

A running JVM can't cleanly replace its own jar, so the backend writes an
`update.flag` and exits; the tray supervisor hands off to `launcher/update.ps1`,
which rebuilds and relaunches, while the UI waits and reloads. The backend
periodically checks GitHub and shows a badge with the number of new commits. The
buttons disable themselves in deployments that can't support them (e.g. a jar-only
copy without the source tree, or without a git checkout).

## Adding a topic by hand

Run a coding-agent CLI at the repo root with the contract and your question, e.g.:

```powershell
Get-Content prompts/add-topic.md | claude -p
```

Then paste the interview question when prompted, or append it to the prompt. See
`AGENTS.md` → "Topic Authoring" for the per-mode file requirements.

## Notes / caveats

- This is a **local personal tool**. The runner relies on a timeout + heap cap +
  child process, not full container isolation. Don't expose it publicly as-is —
  the LAN access above assumes a trusted home network.
- Generation runs the coding agent with a bypass/auto-approve permission mode
  (configurable under `app.ai.*` in `application.yml`) so it can write files
  headlessly.
- Never commit `config/secret.yml`, `.dev-pids`, logs, build outputs,
  `node_modules`, or `frontend/dist`.
